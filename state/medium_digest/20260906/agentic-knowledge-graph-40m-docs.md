## 한글 요약

핵심 주장은 한 줄로 요약된다: **그래프를 LLM으로 "추출"하지 말고, 이미 엣지를 갖고 있는 코퍼스를 "파싱"하라.** 저자는 MS GraphRAG 인덱싱이 데이터셋 하나에 약 3만 3천 달러(그중 3/4가 그래프 추출 비용)가 든다는 공개 수치를 출발점으로 삼는다. 그래서 GraphRAG 데모는 문서 수천 건에서 멈춘다. 반대로 PubMed는 NLM이 이미 큐레이션한 인용 링크·MeSH 주제어·정정 이력을 레코드 안에 실어 배포하므로, 모델 호출 0회로 4천만 문서에서 9억 2,982만 엣지를 10.8분(초당 6.1만 레코드)에 뽑아낼 수 있다. 그래프DB도, 추출 모델도 쓰지 않고 순수 파이썬 46개 모듈로 구성했다.

제목의 9.3억과 실제 에이전트가 걷는 그래프 크기가 다르다는 점을 저자가 먼저 밝힌다. 화학물질·문헌유형·정정 테이블도 파싱해 저장하지만 순회에 쓰는 것은 인용 + MeSH 주제어 뿐이라 7.4억 엣지다. 두 숫자 다 진짜이고 서로 다른 것을 잰다는 태도가 글 전체의 성격을 보여준다.

코퍼스를 전부 써야 하는 이유는 감으로 정한 게 아니라 측정으로 정했다. 원래 계획은 최근 1천만 건 슬라이스였는데, 유도 부분그래프 유지율을 먼저 재보니 최근 1천만 건은 인용 엣지의 **28.1%**만 남고 MeSH 커버리지도 63.6%로 떨어진다. 전체 4천만 건에서는 유지율이 100%(3.97억 중 dangling 1,649개뿐)다 — NLM이 PMID로 해소된 참조만 기록하기 때문에 조인을 큐레이터가 미리 해준 셈이다. 연대별로 쪼개보면 이유가 선명하다. 1950년대 문헌은 MeSH 색인 98% / 초록 0.4%, 2020년대는 MeSH 71% / 초록 87%로 정확히 거울상이다. 두 레이어가 겹치는 시기가 없으니 둘 다 확보하려면 전체를 써야 한다.

저장 계층은 그래프 데이터베이스를 감사한 뒤 기각했다. 벌크 로더가 없어 노드를 CREATE 한 건씩 넣어야 하고, 8억 엣지 × 1~5ms 왕복이면 14~56시간이 든다. 대신 CSR(압축 희소 행)에 memory-map: 소스로 정렬된 엣지 배열에서 노드 i의 이웃은 연속 슬라이스 하나다. 결과는 그래프 로드 2.9ms, 노드 확장 7.6μs(DB 왕복 대비 약 1000배). 인용 역방향 인덱스가 정방향보다 2.3배 많은 문서에 닿는데, 논문은 수십 편을 인용하지만 수천 편에게 인용될 수 있기 때문이다.

온톨로지도 만들지 않고 빌려왔다. MeSH 디스크립터 31,110개, 엔트리 용어 267,012개, 트리 번호가 `C14.280.647.500` 같은 점 구분 경로라 **조상 탐색이 문자열 접두어 슬라이싱**으로 끝난다 — 추론기(reasoner)도 Datalog도 필요 없다. 보조 개념 레코드(SCR) 32만 건은 새 노드가 아니라 기존 디스크립터로의 별칭이라 그래프 구조를 건드리지 않고 커버리지만 올린다.

질문을 개념에 매핑하는 grounder에는 **모델을 일절 넣지 않는다** — 할루시네이션이 들어올 수 있는 지점이라서, 모델이 식별자를 생성할 수 없게 최장일치 사전 탐색만 쓴다. v1은 실제 질문의 51%만 커버했고, 저자는 실패 300건을 손으로 분류해 영국식 철자(oesophagus/tumour/paediatric), MeSH의 도치형 표기(`Circumcision, Male` vs "male circumcision"), 과도한 카테고리 필터를 원인으로 특정했다. 철자 치환 27규칙 + 도치 해제로 74%, SCR 별칭 추가로 81%까지 올렸다.

여기서 이 글의 가장 값진 대목이 나온다. 81%에서 그냥 출시할 뻔했는데, **커버리지는 "뭐라도 매칭했나"만 묻는 지표라 모든 단어를 매칭하면 최대화된다.** 그래서 지표를 바꿨다 — 정답 문서에 원래 달려 있는 MeSH 헤딩(저자가 만들지 않은 ground truth)에 대한 정밀도로. 재보니 head-noun 매칭은 커버리지 7점을 벌고 정밀도 0.075를 잃었다: "decrease"가 Population Dynamics로, "results"가 Reproducibility of Results로 매칭되는 문법적 사고였다. 기능을 폐기하고, 단일 단어 매칭은 일상 영어면 차단하는 가드(관측된 오탐 109단어)를 넣었다.

증거 탐색은 두 종류다. DIRECT는 두 디스크립터를 모두 major topic으로 단 논문 한 편(NLM이 직접 단언한 것이라 가장 강함), BRIDGE는 개념 A 논문이 개념 B 논문을 인용하는 1홉이다. 질문이 개념 3~4개를 언급할 때 어느 쌍을 연결할지는 규칙이 아니라 그래프가 정한다 — 쌍마다 공동 주석 문서를 교집합해 가장 큰 쪽을 고른다. "아스피린이 심근경색 위험을 줄이나"에서는 Aspirin↔Myocardial Infarction이 1,132건으로 뽑히고, "risk"는 특이성 필터를 통과하지만 공동 주석이 거의 없어 그래프가 알아서 버린다. Humans(2,322만 건)·Male 같은 체크 태그는 순회하면 2천만 논문을 "증거"라 부르게 되므로 문서 수 임계로 제외된다.

거절(refusal)은 모델의 겸손이 아니라 **빈 결과 집합**이다. 6개 게이트 중 5개가 생성기를 로드하기도 전에 도는 numpy 술어다: 디스크립터로 해소되는 게 없음 → 특정 개념 2개 미만 → 경로 없음 → 인용 가능한 종점 없음(4천만 노드 중 초록 있는 건 2,833만, 즉 인용할 수 없는 노드를 통과해 순회할 수는 있다) → 철회/정정된 증거뿐 → as-of 날짜 이전 증거 없음. 마법 주문 질문은 게이트 1에서, 2020년 질문을 "2015년 기준"으로 물으면 경로 362개를 찾고도 0개만 남아 게이트 6에서 거절된다.

"추적 불가능한 것은 거절한다"는 인과 주장이므로 절제(ablation) 실험으로 검증한다. 증거를 단계적으로 지우며 거절률을 본다: 전체 그래프 7.5% → 정답 문서 제거 7.5% → 직접 공동 주석 증거까지 제거 20.8% → 브리지 종점까지 제거 100%. 단조 증가에 인과 효과 +92.5점. 안쪽 두 눈금이 더 흥미롭다 — 정답 문서 하나를 지워도 아무 변화가 없다(4천만 문서에서 단일 논문이 유일 증거인 경우는 없다), 직접 증거를 전부 지워도 79%가 살아남는다(인용 브리지가 실질적 중복성을 준다).

두 번의 조용한 버그가 이 글의 다른 축이다. 첫째, MeSH major-topic 플래그를 별도 패스에서 다른 중복 제거 규칙과 ORDER BY 없이 만들어 `major[k]`가 `indices[k]`와 다른 논문을 가리켰다 — 크래시도 예외도 없이, 추적 가능성이 존재 이유인 시스템에서 증거가 남의 플래그를 달 뻔했다. 둘째, 임베딩 랭커의 캐시를 첫 질문의 식별자 집합에 키잉해 이후 모든 질문이 조용히 -1점을 받고 임의 순서로 폴백했다. 둘 다 "그럴듯한 숫자"를 냈지 에러를 내지 않았다. 처방은 **내부 불변식 assert + 소스로부터의 독립 재집계** 둘 다 걸기다.

2,830만 초록 임베딩에서는 GPU가 아니라 공급이 병목이었다. 3,300만 파라미터 모델과 1.1억 파라미터 모델이 같은 초당 처리량을 냈다는 게 단서 — 작은 쪽이 3배 빨라야 하는데 같다면 GPU가 놀고 있다는 뜻이다. 파일 40개를 슈퍼샤드로 묶어 길이순 전역 정렬 후 상주 워커 풀에 넘기니 620 → 3,718 texts/s(6배)로 올랐고 모델은 바꾸지 않았다. 측정된 상한 13,396 대비 28% 수준이고 첫 버전은 5% 미만이었다. 곁가지로, `TOKENIZERS_PARALLELISM=true` + DataLoader 워커 조합은 Rust 토크나이저 스레드풀이 fork()를 못 넘겨 교착한다(증상: 프로세스 14개가 GPU 0%로 무에러 정지).

마지막 게이트 6은 명제적 검증이다. 경로는 개념이 공기(共起)한다는 것만 증명할 뿐 극성은 그래프 속성이 아니다 — 아스피린이 돕든 해롭든 1,132건에 같이 등장한다. 함의(entailment) 모델을 SciFact로 독립 검증했는데, 첫 평가에 교락이 있었다: SUPPORT/CONTRADICT에는 정답 근거 문장을, NOINFO에는 초록 전체를 먹여서 길이만으로 분류가 됐다. 누수를 제거하자 zero-shot macro-F1이 0.597에서 0.464로 떨어졌다 — 첫 평가의 1/3이 문장 길이를 재고 있었다. 919쌍 3에폭(H100에서 약 100초) 적응 후 NOINFO AUROC는 0.722 → 0.932로 올랐다.

그리고 저자는 자기 주장을 좁히는 **음성 결과**를 그대로 싣는다. MedREQAL(코크란 리뷰의 "근거 불충분" 판정)에서 사전에 두 가설을 적어두고 돌렸다: H1(구조적 게이트만으로는 분간 못 함)은 지지됐지만(AUROC 0.555), H2(게이트 6이 분간함)는 기각됐다(0.497 = 우연 수준). SciFact에서 0.932를 낸 바로 그 검증기가 여기선 동전 던지기다. 튜닝 대신 진단을 돌려 세 설명을 분리했다 — 검증기 자체가 망가졌나(SciFact 재검사 0.932로 기각), 검색이 잘못됐나(코크란의 결론 텍스트를 직접 먹여도 0.544에 그쳐 기각), 아니면 과제의 종류가 다른가. 남은 건 세 번째다: 문서 단위 모델이 할 수 있는 일이 아니다.

에이전트 설계 관점에서 가장 뼈아픈 결론은 따로 있다. 저자는 진짜 피드백 엣지를 가진 LangGraph 루프를 만들었다가 **기각했다** — 측정할 때마다 평범한 파이프라인보다 나빴다. 최종 성적은 600개 held-out 질문에 83.2%이고, 저자 본인 코드의 상수 하나가 14점어치였다고 적는다.

**적용 각도(참고용 메모)**: 우리 dcsai KG 작업과 정면으로 닿는다 — 사내 데이터는 이미 스키마와 관계가 정의돼 있으니 LLM 추출이 아니라 파싱으로 그래프를 세우는 쪽이 비용·정합성 모두 유리하다. 특히 (1) "거절 = 빈 결과 집합"으로 게이트를 코드 술어로 만들어 생성기 앞단에 두는 설계, (2) 커버리지 대신 기존 메타데이터를 ground truth 삼은 정밀도 지표, (3) 크래시 없이 그럴듯한 숫자를 내는 정렬 버그에 대비한 "불변식 assert + 독립 재집계" 습관은 ai_news_agent 파이프라인의 x_trends 링크 검증(코드가 직접 매칭해 URL 할루시네이션 방지)과 같은 철학이다. LangGraph 루프 기각 사례는 에이전트 프레임워크를 기본값으로 깔기 전에 평이한 파이프라인과 실측 비교해야 한다는 근거로 쓸 만하다.
