## 한글 요약

macOS 27이 `/usr/bin/fm`이라는 CLI를 조용히 추가했다는 발견기다. Apple Foundation Models(애플 인텔리전스를 구동하는 LLM들)를 터미널에서 직접 부르는 도구로, 계정도 인터넷도 없이 동작한다. 저자는 가장 저렴한 애플 실리콘 맥인 M1 8GB 맥북 에어에서 하루 종일 만져보고 정리했다.

먼저 기대치 설정. 이건 Opus나 GPT-5.5급이 아니다. 작은 모델이고, 메모리가 작고, 오늘 날짜를 모르고, 가끔 태연하게 거짓말을 한다. 그래도 자잘한 작업용 무료 AI가 필요하다면 진짜 쓸모가 있다.

명령 뒤에는 두 모델이 있다. **system** — 기기 내장 모델. 맥에서 오프라인·무료로 돌고 기본값이다. **pcc** — 같은 발상의 더 큰 모델로, 애플의 Private Cloud Compute 데이터센터에서 돈다. 모델 자체가 새것은 아니다. Foundation Models 프레임워크는 macOS 26부터 있었고 단축어 앱의 "Use Model" 동작으로 대화할 수 있었다(아이폰에서는 여전히 그게 유일한 경로다). **macOS 27이 추가한 것은 파이프로 넘기고 스크립트에 엮을 수 있는 평범한 CLI**이고, 저자는 그게 진짜 뉴스라고 본다.

주요 기능을 정리하면 이렇다.

**한 줄 질의와 파이프.** `fm respond "질문"`이 기본이고, 시스템 서비스로 지연 로딩되므로 첫 워밍업 후에는 1~2초에 답이 온다. 표준 입력을 읽기 때문에 `cat notes.txt | fm respond`로 파일 요약, `pbpaste | fm respond`로 클립보드 처리, 로그 파일을 밀어 넣고 "여기 에러가 뭐냐"를 물을 수 있다. 어떤 스크립트나 Automator 동작에도 끼워 넣을 수 있는 진짜 프라이빗 AI 단계가 된다. 저자는 여기서 겪은 실패를 **일부러 남겨뒀다** — 단축키를 물었더니 정확한 답(복사·붙여넣기·실행취소) 앞에 "애플 로고가 화면에 표시되는데 이는 애플이 개발한 파운데이션 모델이며…"라는 지어낸 첫 문장이 붙었다. 형태와 속도는 믿되 진리로 믿지는 말라는 것.

**세션과 이미지.** `fm chat`은 답하고 끝나지 않고 대화를 유지하며, 모든 세션이 `~/.fm/sessions/`에 JSON 기록으로 저장된다. `/exit` 하면 재개 명령을 출력해 다음 날 정확히 그 대화를 이어받을 수 있고, 파일은 내 디스크에 있으니 언제든 지울 수 있다. `--image`로 파일을 가리키면 모델이 볼 수도 있다 — 저자가 자기 메뉴 바 캡처를 넣었더니 8GB M1에서도 정확히 설명했다. 스프레드시트를 사진에서 풀어내진 못하지만 "이 그림에 뭐가 있나" 수준이나 대략적 OCR성 질문에는 오프라인으로 동작한다.

**구조화 출력(저자 최애).** 모델에게 엄격한 JSON 형태로만 답하도록 강제할 수 있다. 장황한 설명도 마크다운도 없이 스크립트가 바로 먹을 수 있는 데이터가 나오고, `fm`이 스키마를 대신 만들어 주기까지 한다. 중첩 객체와 배열도 된다. 이메일에서 연락처 추출, 영수증에서 품목 뽑기, 노트 폴더 태깅 — 로컬·무료·프라이빗한 "지저분한 텍스트를 구조화 데이터로" 기계다. 저자가 실제 워크플로를 짜겠다고 꼽은 기능이다. 분류 전용으로는 `--use-case content-tagging`이 산문 대신 키워드를 돌려준다.

**4,096 토큰 벽.** 온디바이스 모델의 컨텍스트는 지시문·프롬프트·답변을 **전부 합쳐** 4,096 토큰, 대략 3,000단어다. 중요한 건 초과 시 동작이다 — 앞부분을 조용히 잊고 계속하지 않고 "세션 기록이 모델 컨텍스트 크기를 초과했다"는 에러로 **멈춘다.** 창 안에서는 말한 걸 다 기억하고, 넘어가면 새 세션을 시작해야 한다. 그래서 미리 재는 `token-count` 도구가 있고, 이 구조가 `fm`이 "이 문단을 요약해줘"에는 훌륭하고 "이 소설을 읽어줘"에는 쓸모없는 이유다. (pcc는 32K 안팎으로 훨씬 넉넉하다.)

**설정 플래그.** `--instructions '너는 직설적인 코드 리뷰어다'`로 시스템 프롬프트를 주고, `--greedy`로 출력을 결정론적에 가깝게 만들고(스크립트에 유용 — 저자가 애완 돌 이름을 물으니 일관되게 같은 답), `--set-default-model`로 기본 모델을 고정하고, `--guardrails permissive-content-transformations`로 정당한 텍스트 변환 작업(소설 편집 등)에서 과민한 안전 필터를 완화하고, `--save-transcript`/`--load-transcript`로 대화를 스냅샷 떠서 다음 세션의 씨앗으로 쓴다. 저자 평가로는 **`--instructions` + `--greedy` 조합이 `fm`을 실제 스크립트에 넣을 만큼 신뢰성 있게 만드는 지점**이다.

**`fm serve` — 로컬 OpenAI 호환 엔드포인트.** 저자가 숨은 핵심으로 꼽는 기능. OpenAI API 형식을 말하는 로컬 웹 서버를 띄운다(기본 포트 1976 — 애플 창립 연도). OpenAI를 기대하는 어떤 도구든 — 파이썬 스크립트, VS Code 확장, 채팅 앱 — API 키도 청구서도 없이 내 맥을 가리키게 할 수 있다(모델 이름은 `system` 또는 `pcc`). 포트 대신 유닉스 소켓을 쓰는 `--socket`도 있다. 여기서 두 가지 사실이 결합해 재미있어진다. 첫째, 기본은 127.0.0.1이지만 `--host 0.0.0.0`을 붙이면 네트워크 전체에 열린다. 둘째 — 저자도 놀란 부분 — **온디바이스 모델은 더 좋은 맥에서 더 똑똑해진다.** M1/M2는 약 3B 소형 모델을 돌리고, 메모리 12GB 이상의 M3/M4(기본형 M4 맥미니나 맥 스튜디오)는 훨씬 큰 약 20B 모델을 돌린다. 같은 명령, 눈에 띄게 나은 답. 그래서 공유기 뒤의 강한 맥 한 대가 집 안 모든 폰과 노트북에 더 나은 AI를 서빙하고 싼 노트북들은 씬 클라이언트로 남을 수 있다. 아이폰은 터미널이 없어 `fm`을 못 돌리지만 맥 주소로 POST 하는 단축어면 충분하다(글에 단축어 구성 단계가 나온다).

여기서 저자가 진지하게 받아들이라고 강조하는 보안 사항 — **`fm serve`에는 비밀번호가 없다.** 포트에 닿을 수 있는 건 무엇이든 쓸 수 있다. 그러니 카페 와이파이가 아니라 집 와이파이에 한정하고, 밖에서 쓰고 싶으면 포트를 인터넷에 던지지 말고 Tailscale 같은 프라이빗 메시를 쓰라는 것. 네트워크에 낸 문으로 취급하라 — 실제로 그게 맞으니까.

**Private Cloud Compute.** `--model pcc`로 애플 서버 측 모델을 부른다. 상태를 저장하지 않고(프롬프트가 질문에 답하면 사라지고 저장되지도, 애플에게 보이지도 않는다), 애플이 서버 코드와 암호학적 증명을 공개해 독립 연구자가 검증할 수 있게 했다는 점이 특징이다. 챗봇 회사에 삶을 넘기고 싶지 않은 사람을 위한 답이라는 포지션. 클라우드라서 칩·RAM과 무관하게 모든 맥이 동일한 모델을 받고, 컨텍스트가 32,768 토큰(온디바이스의 8배)으로 열린다. 다만 무한하지 않다 — Apple 계정에 묶인 사용자별 일일 할당량이 있고(그래서 `fm quota-usage` 명령이 있다), 애플은 한도를 올리는 방법으로 iCloud+를 가리킨다. 즉 "영원히 무료인 무제한 프론티어 AI"는 아니다.

FAQ 중 실무적으로 중요한 두 가지. **메시지나 메모를 읽지 못한다.** 저자가 이름·최근 메모 3개·캘린더·마지막 문자·바탕화면 파일·배터리 잔량·현재 시각까지 집요하게 물었지만 전부 "사용 불가", "금지됨", "접근할 수 없음"이 돌아왔다. 시간조차 모른다. 웃긴 건 그 전에 모델이 "네, 저는 당신의 메모·메시지·파일에 접근할 수 있습니다"라고 쾌활하게 답했다는 것 — 완전한 환각이었다. **작은 모델은 자기 자신에 대해서도 자신 있게 지어낸다는 교훈.** 사람들이 헷갈리는 "개인 컨텍스트"(엄마가 지난주에 보낸 사진을 찾아주는 의미 인덱스)는 Siri의 기능이지 이 모델의 것이 아니다. `fm`이 말하는 모델은 의도적으로 백지이고 프라이빗한 상태이며, 내가 건네기로 선택한 텍스트만 본다. 나중에 채워질 베타의 공백이 아니라 설계이고 저자는 그게 옳은 설계라고 본다 — 원하면 `cat notes.txt | fm respond`로 언제든 내 데이터를 의도적으로 줄 수 있다.

**얼마나 똑똑한가.** 오늘이 2024년 9월 11일이고 아이폰 15가 최신이라고 생각한다. 세계 지식이 얇고 얼어붙어 있으며 웹을 볼 수 없다. 애플도 온디바이스 모델은 범용 지식 챗봇으로 만든 게 아니라고 명시한다 — 요약·추출·분류·재작성·구조화를 위한 것이고, 그 작업들에서는 온디바이스·무료로 매우 잘한다. 벤치마크 위치는 애플 자체 테스트 기준 동급 소형 모델(3~4B Qwen·Gemma 계열)과 대등하고, 독립 평가는 대략 Gemini Nano/소형 Llama 티어로 본다. PCC는 한 체급 위로, 애플 수치상 일부 중형 오픈 모델을 이기지만 진짜 프론티어에는 못 미친다. Ollama나 LM Studio를 대체하느냐는 질문에는 — 일상적 잡무(텍스트 정리, 요약, 데이터 추출)라면 설치 없이 그렇다, 하지만 70B급을 돌리거나 자기 파인튜닝 가중치를 올리려면 그것들을 유지하라고 답한다.

macOS 26 사용자를 위한 경로도 있다. 모델 자체는 26부터 있었고 `fm` 명령만 새것이라, `pip install apple-fm-sdk`(애플 공식 파이썬 패키지)나 커뮤니티 CLI(apfel, afm)로 같은 모델을 오늘 쓸 수 있다.

저자가 반복해서 돌아가는 세 가지는 오프라인으로 지저분한 텍스트를 깨끗한 JSON으로 바꾸는 `fm respond --schema`, 즉석 프라이빗 요약을 위한 파일 파이핑, 그리고 자기 스크립트용 무료 OpenAI 호환 엔드포인트인 `fm serve`다.

**적용 각도(참고용 메모)**: `fm serve`의 OpenAI 호환 엔드포인트는 우리 LLM 백엔드 폴백 사슬(claude -p → LiteLLM)에 **네트워크 없이도 도는 최후 단계**로 검토해볼 여지가 있다 — 다만 4,096 토큰 벽 때문에 요약·분류 같은 짧은 호출(예: x_trends의 extract_keywords)에나 맞고, 컨텍스트가 큰 다이제스트 생성에는 부적합.
