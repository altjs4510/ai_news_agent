## 한글 요약

2026년 4월 3일 Andrej Karpathy가 "LLM Knowledge Bases"라는 아이디어를 트윗했다. 매 질문마다 RAG로 원본 파일 청크를 검색하는 대신, LLM이 파일 더미를 한 번 컴파일해서 요약·백링크·개념 맵·인덱스가 붙은 구조화된 마크다운 위키로 만들어 두고, 이후 세션들이 그 위키를 탐색하게 하자는 것. 세션을 넘어 지식이 누적되고 이후 쿼리는 훨씬 싸진다. 벡터 임베딩도 검색 파이프라인도 없이 "복리로 쌓이는 마크다운 파일"이면 된다는 발상이 커뮤니티에서 폭발적으로 퍼졌다.

트윗 48시간 뒤, Safi Shamsi라는 개발자가 이 패턴을 코드베이스용으로 실제 구현한 오픈소스 도구 **Graphify**를 출시했다. 폴더 하나를 가리키면 19개 언어의 코드, PDF, 마크다운, (Claude Vision을 통한) 화이트보드 사진·다이어그램 이미지까지 파싱해 커뮤니티 탐지가 적용된 지식그래프를 만든다. 산출물은 인터랙티브 HTML 시각화(graph.html), god node와 의외의 연결을 짚어주는 GRAPH_REPORT.md, 쿼리 가능한 graph.json, 그리고 재처리를 피하는 증분 캐시. `pip install graphifyy && graphify install` 한 줄로 설치되고, Claude Code(또는 Codex/OpenCode 등) 안에서 `/graphify`로 실행한다. 저자가 강조하는 것: 이건 RAG도, 벡터 DB도, 챗봇 래퍼도 아니고 Karpathy가 말한 "컴파일 단계"다.

핵심 주장인 **"쿼리당 토큰 71.5배 절감"**에 대해 저자는 회의부터 걸고 검증했다. 6개 파일 수준의 작은 규모에선 압축 효과가 미미하고(어차피 컨텍스트에 다 들어감) 구조 파악 정도가 이득이다. 코드+논문+이미지가 섞인 52개 파일 코퍼스에서는 실제로 71배가 나오는데, 레포가 원본 입력과 실제 출력을 함께 공개해 직접 검증 가능하다. 압축이 스케일하는 이유는 단순하다 — 그래프가 노드·엣지·커뮤니티 요약·리포트로 정보를 증류하므로, LLM이 원문 전체를 읽는 대신 훨씬 적은 토큰으로 구조 정보를 순회할 수 있기 때문. 병렬 에이전트 여러 개가 코드를 쓰거나 여러 커밋에 걸친 긴 Claude Code 세션에서는 매 턴 원본 파일을 다시 먹이는 것과 근본적으로 다른 비용 구조가 된다.

내부 구조는 투명하다. 코드는 tree-sitter AST 파싱(로컬 전용, LLM 호출 없음, 코드 내용이 머신을 떠나지 않음), 문서·이미지는 플랫폼의 기존 모델 API(Claude Code면 Claude)로 시맨틱 추출. NetworkX로 그래프 구축, graspologic의 Leiden 알고리즘으로 커뮤니티 탐지, vis.js로 시각화 — Neo4j나 외부 서버 불필요. 모든 엣지에 EXTRACTED/INFERRED/AMBIGUOUS 신뢰도 태그가 붙어 "소스에서 찾은 것"과 "모델이 추측한 것"이 구분된다. `--watch` 모드는 코드 저장 시 LLM 호출 없이 AST만 즉시 재빌드하고, git hook은 커밋·브랜치 전환마다 그래프를 재빌드하되 실패 시 non-zero로 종료해 조용히 낡은 그래프가 쓰이는 것을 막는다(이전 버전은 실패해도 0으로 종료하는 침묵 실패가 있었다).

저자가 자기 레포(Claude Code로 만든 QR 코드 생성기, 27개 파일)에 직접 돌린 결과가 흥미롭다. 4단계 파이프라인(스캔→로컬 AST 파싱으로 162노드/240엣지→Claude 서브에이전트 6개 병렬로 문서·이미지 읽기 약 193k 토큰→병합해 229노드/296엣지, 26개 커뮤니티). 비전 에이전트는 UI 스크린샷을 실제 인터페이스 요소로 이해해 "로고 드롭존이 QR 프리뷰 패널과 데이터를 공유한다" 같은 연결을 만들었다. 그래프가 드러낸 비자명한 사실: 이 레포의 무게중심은 QR 인코딩이 아니라 색 과학(대비·팔레트·색 추출 수학)이었고, QR 인코딩은 주변부의 라이브러리 의존성 2개에 불과했다. 스펙 문서(AGENTS.md 등)의 개념들은 의미상 코드와 일치하지만 구조적으로는 연결이 없는 섬으로 나타났다. 실행 후 `/graphify` 스킬이 등록돼 이후 세션에서 `graphify query "왜 다운로드 버튼이 비활성으로 시작하나?"`처럼 레포 재독해 없이 그래프에 질의할 수 있다.

정직한 한계도 정리돼 있다. v0.3.1이라 거칠고, 시맨틱 추출 품질은 전적으로 기반 LLM(특히 비전)에 달렸다. 71.5배는 코퍼스 의존적이라 README 있는 10개 파일 프로젝트엔 불필요하다. HTML 시각화의 SSRF·YAML 인젝션 보안 패치가 최근에야 들어갔으니 민감한 코드베이스엔 보안 표면을 직접 검토하라. 그리고 가장 중요한 것 — 그래프는 "무엇이 무엇과 연결되는지"는 알려주지만 "왜 그런 트레이드오프를 했는지"는 못 알려준다. 그 맥락은 여전히 PR 논의와 커밋 메시지, 팀의 머릿속에 있다.

저자의 결론: "토큰을 코드 생성에 쓰는 것"에서 "토큰을 지식 컴파일에 쓰는 것"으로의 전환이 본질이고, Graphify는 그걸 코드베이스에 대해 처음으로 신뢰성 있게 구현한 사례다(출시 직후 1,500 스타, .NET 포트 등장). "AI가 코드를 읽는 것"과 "AI가 코드베이스를 이해하는 것"은 다른 능력이며, 매 세션 원본 파일 재주입 방식은 이미 천장에 닿았다. 레포는 MIT 라이선스(github.com/safishamsi/graphify).

**적용 각도(참고용 메모)**: Karpathy의 "컴파일된 지식" 패턴은 우리가 이미 쓰는 OKF/cookie-knowledge 접근과 같은 계열 — Graphify를 hermes나 ai_news_agent 레포에 한번 돌려 god node/구조 드리프트를 보는 것은 5분짜리 실험으로 가치 있음.
