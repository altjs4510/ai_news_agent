## 한글 요약

네트워크 분석의 적용 범위가 전통적 도메인(소셜 네트워크, 생물학, 교통, 정보 흐름)을 넘어 개인 지식 관리로 확장되고 있다는 관찰에서 출발하는 실습 튜토리얼. Obsidian류 도구가 보여주듯 정보를 고립된 문서나 계층 구조가 아니라 개념·아이디어·참조가 상호 연결된 그래프("세컨드 브레인")로 조직하는 흐름이 자리잡았고, 구조화된 지식그래프는 LLM에 컨텍스트를 제공해 비구조 정보와 기계 이해 사이 간극을 줄이는 기반도 된다. 저자는 자신이 만든 Python 라이브러리 **D3Blocks**(D3.js 기반)의 d3graph 컴포넌트로, 서버·프레임워크 없이 단일 HTML 파일로 동작하는 인터랙티브 지식그래프를 만드는 법을 단계별로 보여준다.

기본 사용법은 source-target-weight 3열 데이터프레임을 넣으면 끝. 중복 엣지는 자동 집계돼 반복 상호작용이 올바르게 카운트되고, 노드는 Louvain 클러스터링으로 자동 색칠되며, 상단 슬라이더로 약한 엣지를 끊어가며 강하게 연결된 코어만 남기는 드릴다운 탐색이 가능하다.

글의 중심은 **"어떤 노드가 중요한가"를 보는 다섯 가지 관점**을 각각 최소 예제 그래프로 시연하는 부분:

- **PageRank** — 연결 수가 아니라 "중요한 이웃과 연결됐는가"로 중요도를 매김. 소셜에선 오피니언 리더, 개인 지식그래프에선 핵심 주제를 드러낸다.
- **HITS Hub** — 권위 있는 노드들을 많이 가리키는 "수집가" 노드. 지식그래프에선 개요 노트·인덱스·대시보드 문서가 자연스럽게 허브가 된다.
- **HITS Authority** — 중요한 허브들이 많이 참조하는 노드. 여러 프로젝트 노트가 반복 참조하는 기술 문서가 권위 노드가 된다.
- **Degree 중심성** — 단순 직접 연결 수. 즉각적이지만 연결의 질을 반영하지 못한다.
- **Closeness 중심성** — 모든 노드에 얼마나 빨리 닿는가. 여러 지식 영역을 잇는 다리 개념을 드러낸다.
- **Betweenness 중심성** — 최단 경로들이 지나가는 브로커 노드. 예컨대 "머신러닝" 노트가 수학·프로그래밍·통계·AI를 잇는 다리 역할임을 보여준다.

**커뮤니티 탐지**는 데이터가 정한 자연스러운 그룹(지식 도메인)을 라벨 없이 발견한다. 슬라이더로 엣지를 걸러낼 때 커뮤니티 구조가 실시간 재계산돼 클러스터가 갈라지고 합쳐지는 과정을 눈으로 볼 수 있다.

차별화 포인트 하나는 **통계적 유의성 검정**이다. 밀집 클러스터나 고연결 노드는 우연으로도 생길 수 있으므로, degree 분포를 보존한 무작위 재배선(degree-preserving randomization)으로 랜덤 네트워크를 수백~수천 개 생성해 노드별 PageRank 등의 귀무분포를 만들고, 관측값을 그에 비교해 경험적 p-value/z-score를 계산한다(`network_significance` 함수 하나로 수행). 단순 엣지 셔플은 degree 분포를 망가뜨려 비교가 왜곡되므로 안 된다는 주의도 붙어 있다.

대규모 네트워크(1만+ 노드, 수만 엣지) 렌더링을 위해 엣지를 SVG DOM 요소 대신 HTML 캔버스 레이어에 그리는 하이브리드 방식(노드는 SVG로 유지해 드래그·클릭 보존), 줌아웃 시 라벨 숨김, 물리 시뮬레이션 틱 제한 같은 최적화도 설명한다. 물리 파라미터(네트워크 텐션·엣지 텐션)를 조절하면 Obsidian 특유의 원형 배치 그래프 느낌을 재현할 수 있고, 같은 데이터로 Elasticgraph·Sankey 등 다른 차트로 쉽게 전환된다.

**적용 각도(참고용 메모)**: sources/x_trends.py의 키워드 추세나 블로그 다이제스트 카테고리 간 관계를 d3graph 단일 HTML로 뽑으면 quick-dashboard로 사내 공유하기 좋은 형태 — degree-preserving 유의성 검정은 "이 키워드 급상승이 노이즈인가" 판별에도 응용 가능.
