## 한글 요약

필자는 데이터 사이언티스트로서, AI 활용이 "ChatGPT 로 브레인스토밍하고 Cursor 로 코드 뽑는" 수준에 머무는 게 아니라 데이터 사이언스 워크플로 **전 구간**으로 확장되고 있다는 점을 실제 프로젝트 하나로 검증해본다. 소재는 2019년부터 애플워치로 쌓아온 본인 건강 데이터다.

출발 조건은 이렇다. 원본 익스포트는 1.85GB XML 로 구글 드라이브에 올라가 있고, 6년 전 이 XML 을 파싱하려다 만 코드가 깃허브 저장소에 WIP 상태로 남아 있다. AI 없이 한다면 XML 구조 조사 → 파이썬 파서 작성 → 로컬 데이터셋 생성 → pandas/numpy 로 EDA → 인사이트 정리 순인데, 보고서 수준까지 가려면 최소 하루가 걸린다. 그래서 6년째 WIP 였다는 것.

AI 를 쓴 워크플로는 네 단계로 압축된다. 에이전트가 (1) 구글 드라이브에서 원본을 찾아 내려받고, (2) 옛 깃허브 코드를 참조해 파싱 스크립트를 새로 쓰고, (3) 파싱된 데이터셋을 BigQuery 에 적재하고 (실무 환경을 흉내내려고 일부러 클라우드 DW 를 끼웠다), (4) SQL 로 분석해 리포트를 만든다. 사람은 리뷰어이자 의사결정자 역할만 한다.

핵심 인프라는 MCP 다. 구글 드라이브·깃허브·BigQuery 를 도구로 붙이는데, 저자는 MCP 설정 자체를 에이전트에게 시키는 게 가장 쉽다고 말한다. 드라이브 MCP 는 OAuth 클라이언트 생성 안내까지 붙여 빠르게 잡혔지만, BigQuery MCP 는 **열 번 넘게 실패한 뒤에야** 연결됐다. 다만 매 실패마다 어떻게 테스트하고 무슨 정보가 진단에 필요한지를 명확히 알려줬다는 점을 긍정적으로 평가한다.

실행은 Plan Mode 로 시작한다. 여러 데이터 소스·도구·질문이 얽힌 프로젝트에서는 먼저 과제와 대략적 계획을 던지고, 모델이 되묻는 질문을 거쳐 구현 계획을 확정한 뒤 승인하는 방식이다. 승인 후 에이전트는 13분간 자율 실행해 1차 분석을 내놨는데, 이 시점엔 BigQuery 연결이 계속 말썽이라 로컬에서 처리해버렸고 트러블슈팅을 한 라운드 더 거친 뒤에야 계획대로 DW 에 적재해 질의했다.

여기서 가장 중요한 교훈이 나온다. **1차 출력은 얕았다.** 깊이는 후속 질문에서 나왔다. 예컨대 저자가 "드라이브에 항공권·여행 계획 문서가 있으니 그걸 찾아 여행 기간 중 활동 패턴을 분석해봐"라고 지시하자, 에이전트가 해당 파일들을 찾아 여행 일자를 추출하고 교차 분석을 수행했다. 총 30분 만에 연간 추세·운동 지속성·여행이 활동량에 미치는 영향까지 담고 권고사항과 한계·가정까지 명시한, 이해관계자에게 바로 보여줄 만한 리포트가 나왔다. 저자가 놀란 건 속도보다 "러프한 노트북"이 아니라 "발표용 산출물" 형태로 빨리 수렴했다는 점이다.

데이터 사이언티스트를 위한 시사점으로 세 가지를 든다. 첫째, AI 를 코딩 보조로만 쓰지 말고 데이터 파이프라이닝·모델 배포까지 라이프사이클 전체로 역할을 넓힐 것. 둘째, **컨텍스트가 배수 효과를 낸다** — 이 워크플로를 강하게 만든 건 모델이 아니라 MCP 였다. 회사 환경이라면 승인된 범위에서 슬랙·메일 MCP 로 과거 논의를 찾고, 위키 MCP 로 테이블 문서를 읽고, DW MCP 로 스키마를 탐색하게 할 수 있다. 셋째, 규칙(rules)과 재사용 가능한 스킬을 정의해 에이전트를 유도하고 능력을 확장할 것.

역할 변화에 대한 관점도 분명하다. 수작업 실행은 줄고 문제 정의가 늘어난다 — 산출물 품질이 문제 프레이밍 품질에 크게 좌우되기 때문이다. 도메인 지식은 여전히 결정적이다. 저자 사례에서 AI 는 "2020년 이후 활동량이 크게 떨어졌다"는 사실은 잡아냈지만 원인은 못 짚고 "루틴 변화·업무 일정·부상·동기 저하 등이 가능하나 이건 추론이지 발견이 아니다"라고 정직하게 물러섰다. 실제 원인은 팬데믹과 재택근무 전환이었다. 회사의 모든 문서에 접근할 수 있다는 게 비즈니스 뉘앙스를 이해한다는 뜻은 아니라는 것. 인과추론처럼 통계적 판단이 강하게 요구되는 작업은 아직 독립 수행을 맡기지 않겠다고도 덧붙인다.

경고도 세 가지다. 데이터 보안 — 개인 사이드 프로젝트라 드라이브 전체 접근을 열었지만 스스로도 위험한 선택이라 인정하며, 회사에서는 반드시 승인된 도구·방식을 따르고 모든 승인 요청 명령을 읽고 누르라고 한다. 코드 검증 — 복잡한 업무 환경에서는 granularity 가 다른 테이블을 조인해 팬아웃·중복 집계를 일으키거나 필수 필터를 빠뜨리는 실수가 여전히 나온다. 마지막은 부작용 이야기인데, 다음날 512GB 맥북 저장공간이 꽉 찼길래 추궁했더니 에이전트는 "나는 수십 MB 밖에 안 쓴다"고 답했고, 실제로 뒤져보니 트러블슈팅 중 만들어진 MCP 래퍼 로그 파일이 **142GB** 로 불어 있었다.

**적용 각도(참고용 메모)**: "1차 출력은 얕고 깊이는 후속 질문에서 나온다"는 관찰은 ai_news_agent 의 요약 단계에도 그대로 적용된다 — 단발 프롬프트 대신 spotlight 주제에 한해 한 번 더 파고드는 라운드를 두는 게 품질 대비 비용이 싸다. 로그 폭주 사례는 무인 배치의 디스크 감시 필요성도 상기시킨다.
