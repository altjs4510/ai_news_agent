## 한글 요약

필자는 Claude Code 를 쓰다가 20~30분 만에 컨텍스트를 다 태우고 레이트리밋에 걸리는 상황을 반복하다, 파이프라인의 서로 다른 지점을 각각 막는 5중 레이어 구성으로 옮겼다. 결과적으로 세션이 3시간 이상 이어지고 토큰 비용이 크게 줄었다는 것이 글의 주장이다. 구성 파일·훅·스크립트는 별도 공개 저장소로 묶어뒀다.

문제 진단은 단순하다. 도구 출력이 그대로 컨텍스트에 쏟아진다는 것. 저자가 든 예로 테스트 스위트 한 번 돌리면 수천 토큰, 커밋 하나 diff 뜨는 데 2만 토큰대, 500줄짜리 파일 한 번 읽으면 창이 훅 찬다. 그러면 오토컴팩트가 일찍 터지고 히스토리가 날아가며 세션이 죽는다.

레이어는 다음처럼 나뉜다. (1) 코드베이스를 tree-sitter 로 파싱해 지식 그래프로 인덱싱해두고 "이 함수 누가 부르나" 같은 구조적 질문을 파일 읽기 대신 그래프 질의로 답하게 하는 MCP. 저자 측정으로 구조 질의 5건이 파일 단위 탐색 대비 41만 토큰 → 3.4천 토큰 수준으로 줄었다. (2) 도구 출력을 샌드박스 서브프로세스에서 돌리고 BM25 로 로컬 인덱싱한 뒤 요약만 컨텍스트에 돌려주는 "출력 가상화" 레이어 — 전체 출력은 필요할 때 검색으로 다시 꺼낸다. (3) CLI 출력을 제자리에서 압축하는 Rust 바이너리(보일러플레이트 제거·중복 병합·유사 항목 그룹핑). (4) 로컬 프록시로 앉아서 대화 히스토리·시스템 프롬프트·CLAUDE.md 까지 포함해 API 로 나가는 페이로드 전체를 압축하고 KV 캐시 프리픽스를 안정화하는 레이어. (5) 모델 자신의 출력 스타일을 압축 레지스터로 바꿔 인사말·헤지·군더더기를 없애는 플러그인.

글에서 가장 실용적인 대목은 도구 목록이 아니라 **강제(enforcement)** 파트다. 저자의 핵심 주장은 "CLAUDE.md 에 효율적으로 굴라고 천 마디 적는 것보다, 낭비 경로를 막는 훅 하나가 낫다"는 것. 모델은 늘 최소 저항 경로를 택하므로, 효율적인 경로를 *유일한* 경로로 만들어야 한다는 논리다.

구체적 게이트 패턴이 흥미롭다. 세션의 첫 Grep/Glob/Read/Search 호출을 PreToolUse 훅이 한 번 막고 그래프 도구를 먼저 쓰라고 밀어낸다. 그래프 MCP 도구가 한 번이라도 실행되면 PostToolUse 훅이 마커 파일을 떨어뜨리고, 그때부터 게이트는 스스로 비켜선다. PPID 스코프의 임시 플래그 두 개로 도는 짧은 상태 기계이고, 한 번 막힌 뒤에는 자동 해제되므로 세션이 교착되지 않는다. 별도로 SessionStart 훅이 규약을 재주입해 중간에 잊는 것을 막는다.

두 번째 훅은 Bash 우회 차단이다. `cat`·`grep`·`find` 류를 Bash 로 직접 돌리면 압축 레이어를 전부 건너뛰고 raw 출력이 컨텍스트로 직행하므로, 이 명령들을 PreToolUse 에서 막아 압축된 도구 경로로 돌린다. `| head`, `| tail` 같은 잘라내기 파이프도 막는데, 자르기 전에 이미 출력이 흘러들어오기 때문이다. 탈출구로 임시 unlock 파일을 두되 10분 뒤 자동 만료시킨다.

설정 쪽에서 눈에 띄는 것들: 오토컴팩트를 컨텍스트 95%가 아니라 50% 지점에서 당겨 터뜨려 천장에 붙지 않게 하기, 서브에이전트 모델을 한 단계 낮은 모델로 고정해 리서치·리팩터·감사 같은 위임 작업 비용을 낮추기, 프롬프트 캐시 TTL 을 5분에서 1시간으로 늘리기. MCP 서버는 딱 두 개만 상시로 두고 나머지는 CLI 나 훅으로 대체한다 — 안 쓰는 MCP 서버도 도구 설명만으로 컨텍스트를 조용히 갉아먹기 때문이다.

저자가 솔직하게 붙인 단서도 중요하다. 이건 공짜 승리가 아니다. MCP 서버들은 세션 시작 시 도구 정의를 싣기 때문에 **짧은 콜드스타트 세션에서는 오히려 손해**다. "인증 어디서 처리해?" 같은 단발 질문이면 맨 Claude Code 가 더 싸다. 절감은 고정비를 치른 뒤 — 파일을 여러 개 읽고, 긴 로그를 뒤지고, 큰 diff 를 보고, 에이전트를 조율하는 실제 작업량이 쌓일 때 — 나타난다.

보안 경고도 한 절을 차지한다. 권한 프롬프트를 줄이는 설정은 사람 체크포인트를 줄인다는 뜻이고, 설치 스크립트가 여러 서드파티 소스에서 코드를 끌어오며, 이 레이어들은 프롬프트·도구 출력·코드·로그·세션 데이터를 다 볼 수 있다. 에이전트 메모리를 레포 하위에 심링크하는 훅은 시크릿이 커밋될 위험이 있으니 gitignore 하라고 못박는다.

마지막에 이 스택이 열어주는 워크플로가 붙는다: 계획 → 구현 → 병렬 서브에이전트 리뷰 스웜(린트·타입·보안·성능·스키마) → **다른 벤더 모델로 교차 리뷰**. 같은 계열 모델끼리 리뷰하면 같은 맹점을 공유하므로 벤더를 바꾸는 게 더 많이 잡힌다는 관찰이고, 다만 "Opus 출력을 Haiku 로 리뷰하지는 말라"는 하한선을 둔다.

**적용 각도(참고용 메모)**: ai_news_agent 는 이미 `claude -p` 구독 백엔드를 쓰는데 콜당 ~35k 베이스라인 토큰이 든다 — 이 글의 "안 쓰는 MCP·도구 정의가 조용히 컨텍스트를 먹는다"는 지적이 그 베이스라인의 정체를 설명하고, 배치 실행 프롬프트에서 불필요한 MCP 를 끄는 것만으로 5h 롤링 한도 여유를 벌 수 있다.
