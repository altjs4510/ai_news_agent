## 한글 요약

Anthropic이 "LLM이 이제 대규모로 취약점을 찾고 고칠 수 있다"고 보인 뒤, 저자는 그 여섯 단계 방어자 루프(위협 모델링 → 샌드박스 → 발견 → 검증 → 트리아지 → 패치)를 프론티어 모델이 아니라 GPU 한 장에서 도는 7B 오픈 모델(Qwen2.5-Coder-7B)만으로 처음부터 끝까지 구현한 기록이다. 핵심 설계 원칙은 하나다 — 모델의 의견은 증거가 아니며, 새니타이저 아래에서 실제로 크래시가 나야만 그것이 참이다. C 메모리 안전성 버그를 표적으로 삼은 이유도 이 부류는 AddressSanitizer가 "크래시함/안 함"을 객관적으로 판정해 주기 때문이다.

가장 중요한 개념적 이동은 발견과 검증을 분리한 것이다. 발견 단계는 재현율(recall)을 노려 시끄럽게 많이 찾게 두고, 검증 단계는 정밀도(precision)를 노려 재현 안 되는 것을 걷어낸다. 하나의 단계가 둘을 동시에 하려 하면 모델이 몸을 사려 진짜 양성까지 걸러내 버린다는 것이다.

7B 모델을 실전에 쓸 수 있게 만든 장치는 세 가지다. 첫째, 출력을 JSON 스키마로 강제한다 — vLLM의 guided decoding으로 디코딩 시점에 스키마를 지키게 하거나, 실패 시 브레이스 균형을 세는 추출기로 잡담 속 JSON만 뽑아낸다. 둘째, 모델이 약한 일을 대신 처리한다 — 7B는 임의의 바이너리를 base64로 손으로 인코딩하지 못하므로, "글자 A, 그다음 값 65를 200번" 같은 세그먼트 서술로 PoC 바이트를 기술하게 하는 write_poc 도구를 준다. 셋째, 그리고 무엇보다 모델을 심판으로 세우지 않는다.

실행은 전부 잠긴 Docker 컨테이너 안에서 일어난다 — 네트워크 없음, 읽기 전용 루트, 모든 capability 제거, 메모리·프로세스 상한. 발견 에이전트들은 recon이 나눈 독립 focus area마다 하나씩 병렬로 돌며 각자 버그 하나를 찾아 크래시로 증명한다. 결정적인 대목은 에이전트가 "찾았다"고 주장한 것을 호스트가 믿지 않는다는 점이다. 호스트가 에이전트가 쓴 PoC 파일을 직접 다시 읽어 스스로 재폭파(detonate)하고, 그때 크래시가 재현될 때만 CrashArtifact가 생성된다. 저자는 이 "PoC를 직접 실행해 본다"가 이 시스템 최대의 레버라고 못박는다.

검증은 두 방식을 대비시켜 교훈을 준다. 결정적 오라클은 새 컨테이너에서 PoC를 세 번 재폭파해 과반이 크래시해야 통과시킨다. 반면 적대적 검증자(모델 기반)는 "이건 거짓 양성이라고 가정하고 반박하라"는 회의적 에이전트인데, 흥미롭게도 이 7B 검증자는 실제로 참인 버그 세 개를 거짓 양성으로 투표했다. 그런데도 파이프라인은 옳게 굴러갔다 — 판정을 새니타이저가 했기 때문이다. 트리아지는 근본 원인으로 중복 제거하고 루브릭으로 심각도를 매긴다. 다만 모델은 코드 맥락은 알아도 "이 프로그램이 실제로 어떻게 배포·도달되는가"라는 우리 쪽 맥락을 모르므로, 심각도는 사람이 확정할 순위 목록으로만 낸다.

패치 단계는 사다리 검증이 빛나는 곳이다. 패치가 빌드되는가(T0), 원래 PoC가 더는 크래시 안 하는가(T1), 정상 입력이 여전히 동작하는가(T2), 새 발견 에이전트가 변종을 못 찾는가(재공격) — 실패하면 새 크래시 트레이스를 다시 먹여 최대 다섯 번 재시도한다. 심어둔 버그 3개짜리 카나리에서는 세 버그를 모두 찾고·증명하고·패치했다(각각 1·2·3회 시도). 그러나 같은 루프를 실제 오픈소스 라이브러리(cJSON 옛 커밋)에 겨눴을 때 7B 모델은 그럴듯한 공격 지점 네 곳(깊은 중첩, 초장문 문자열, 극단값, 트리키한 유니코드 이스케이프)을 짚었을 뿐 크래시는 하나도 증명하지 못했다. 이것이 바로 정밀도의 프론티어다 — 어디를 볼지 아는 것은 값싸고, 아이디어를 증명된 크래시로 바꾸는 마지막 1마일이 어렵다. 이 지점에만 더 강한 모델을 꽂으면 하류(호스트 재폭파·트리아지·패치 사다리)는 그대로 재사용된다.

**적용 각도(참고용 메모)**: "생성은 모델, 판정은 결정적 오라클" 분리 원칙은 우리 ai_news_agent 파이프라인에도 그대로 닿는다 — LLM이 뽑은 키워드·요약·링크를 코드가 원본 문자열 매칭으로 검증하는 x_trends의 URL 할루시네이션 방지 설계와 같은 철학이고, review-first 게이트나 자동 발행 검증에 "모델 주장 대신 재현 가능한 검사"를 세우는 확장 근거가 된다.
