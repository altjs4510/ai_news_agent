## 한글 요약

필자는 Claude가 시원찮은 결과를 낼 때마다 프롬프트 탓을 했지만, 진짜 원인은 프롬프트가 아니라 작업 폴더였다고 말한다. `final.docx`, `final_v2.docx`, `new_final_REAL.docx` 같은 파일들이 옛날 메모와 현재 초안 사이에 뒤섞여 있는 상태에서는 모델이 무엇을 읽어야 할지 스스로 추측해야 한다. 지저분한 작업 공간은 지저분한 출력으로 되돌아온다는 것이다.

핵심 주장은 한 줄로 요약된다 — **폴더도 프롬프트의 일부다.** 우리가 타이핑하는 텍스트만이 입력이 아니라, 에이전트가 접근할 수 있는 파일 트리 전체가 컨텍스트다. 구조가 없으면 모델은 엉뚱한 초안을 열거나, 이미 폐기된 메모를 현행 사실로 취급하거나, 정작 중요한 파일을 무시한다. 실제 작업 대신 "이 작업 공간이 도대체 어떻게 생겨먹었는지" 파악하는 데 예산을 쓰게 된다.

제안하는 기본 골격은 네 개 폴더(`system/`, `context/`, `projects/`, `outputs/`)이고, 파일 수가 늘어나면 두 가지만 덧붙인다. 첫째, 최상위 레벨에 번호를 붙인다. 둘째, `archive/`를 추가한다. 결과는 `[01] system/`, `[02] context/`, `[03] projects/`, `[04] outputs/`, `[99] archive/` 형태다. 아카이브에 99를 준 이유는 항상 목록 맨 끝에 밀려나면서도 검색 대상으로는 남아 있게 하기 위해서다.

각 폴더의 역할 분담은 명확하다. system은 모델이 반드시 지켜야 할 규칙, context는 모델이 알고 있어야 할 안정적인 배경 지식, projects는 현재 진행 중인 작업, outputs는 완료된 결과물, archive는 낡았지만 검색 가능한 것들. 필자는 폴더 스무 개나 완벽한 분류 체계는 필요 없다고 못 박는다 — 모델이 빠르게 훑을 수 있는 정도면 충분하다.

파일 이름 규칙도 컨텍스트로 취급한다. 모델이 문서를 열기 **전에** 이름만으로 내용을 짐작할 수 있어야 한다는 것이다. 좋은 이름은 세 가지 질문에 답한다: 언제 만든 것인가, 무엇에 관한 것인가, 어떤 상태인가. 시간 정밀도는 파일 성격에 맞춰 다르게 잡는다 — 장기 보관 파일은 연도만, 기획 사이클은 연도+분기, 반복 업무는 연도+월, 개별 태스크 파일은 전체 날짜.

폴더별로 정리 원칙도 다르다. `projects/` 안쪽은 워크플로가 있으니 번호를 매기는 게 맞다(`00_BRIEF.md`, `01_SOURCES/`, `02_NOTES/`, `03_DRAFTS/`, `05_FINAL/` 식). 반면 `context/`는 워크플로가 아니라 **라이브러리**다. 보편적인 읽기 순서가 없으므로 번호 대신 서술적 이름을 쓴다(`HOW-I-WORK.md`, `voice-guide.md`, `audience.md`, 그 아래 `references/`). 재사용 가능한 파일을 프로젝트마다 복사할 필요는 없고, 필요할 때 참조하라고 지시하면 된다.

분류 기준은 단순하다. 여러 프로젝트에 걸쳐 재사용되면 context, 한 프로젝트 전용이면 projects, 끝난 작업이면 outputs, 낡았지만 나중에 쓸지 모르면 archive.

마무리에서 필자는 구조를 외우지 말고 규칙을 외우라고 한다: 지시는 마크다운으로, 순서는 번호로, 의미는 이름으로, 검색은 날짜로, 소음은 아카이브로. 그리고 실행 조언 하나 — 오늘 밤 컴퓨터 전체를 재정리하지 말 것. 그건 파일 관리를 또 하나의 끝나지 않는 프로젝트로 만드는 길이다. Claude가 이미 건드리고 있는 폴더 하나부터 시작해서 구조를 넣고, 중요한 파일만 이름을 바꾸고, 낡은 건 아카이브로 옮기면 된다. 목적은 완벽한 폴더가 아니라 **모델이 추측할 이유를 줄이는 것**이다.

**적용 각도(참고용 메모)**: ai_news_agent의 `state/`·`reports/`·`knowledge/` 디렉토리는 이미 날짜 기반(`YYYYMMDD/`)이라 "날짜는 검색용" 원칙에 부합하지만, 재사용 컨텍스트(카테고리 정의 8종, 프롬프트 템플릿)가 코드 안에 흩어져 있어 context 라이브러리로 분리해두면 CLAUDE.md 가 짊어진 부담을 덜 수 있다.
