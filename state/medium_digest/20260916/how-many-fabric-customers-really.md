## 한글 요약

벤더가 공표한 고객 수를 곧이곧대로 믿지 않고, 공개 커뮤니티 활동 데이터만으로 실제 규모를 역산해 보는 글이다. 필자는 앞선 글("Is Microsoft Fabric Dying?")에서 조직들이 Fabric 에서 발을 빼는 듯하다는 관찰을 마이크로소프트 공식 커뮤니티 포럼과 Reddit 게시글 분석으로 뒷받침했는데, 그 포럼 데이터를 보다가 든 생각이 이 글의 출발점이다 — 2025년 5월에 발표된 "Fabric 고객 2만 1천 이상"이라는 (필자가 보기엔 부풀려진) 수치에 기대지 않고 실제 고객 수를 추정할 수 있을까.

**출발점: 21,000이라는 숫자를 왜 아무도 안 믿는가.** 핵심 논리는 SKU 강제 전환이다. Power BI Premium 의 P SKU 를 Fabric 의 F SKU 로 자동 전환시켰다고 해서 그 고객이 Fabric 을 실제로 쓰는 것은 아니며, 십중팔구 여전히 Power BI 고객일 뿐이라는 것. 필자가 조사 끝에 잡은 비율은 **70%** — 즉 마이크로소프트가 주장하는 "Fabric 고객" 중 70%는 P SKU 에서 F SKU 로 떠밀린 Power BI 고객이라는 추정이다. 근거로는 Power BI Premium 판매가 2024년 6월 30일에 종료됐다는 점을 든다. 2025년 5월에 수치를 낸다는 건 EA(기업 계약) 밖에 있던 P SKU 고객은 거의 전부, EA 고객도 계약이 통상 3년이니 약 3분의 1은 이미 전환됐다는 뜻이라는 것. 그래서 21,000 × (1−0.7) ≈ **6,300개 조직**이 2025년 5월 기준 실제로 Fabric 으로 뭔가를 하고 있는 고객이라는 1차 추정이 나온다. 필자는 이 숫자에 동의하지 않아도 좋으니 왜 더 크거나 작아야 하는지 논리를 달라고 덧붙인다.

**두 번째 독립 경로: 포럼 활동량 비율.** 필자가 계속 눈여겨본 것은 Power BI 포럼 활동이 Fabric 포럼보다 지수적으로 많고, 그 격차가 마이크로소프트 커뮤니티 포럼과 r/MicrosoftFabric 서브레딧 양쪽에서 동일하게 나타난다는 점이었다. 남는 질문은 "그 지수가 몇이냐"다. Power BI 사용자가 약 3,500만 명이고, Tableau 등이 낸 연구에서 리포팅 커뮤니티의 약 15%가 실제 제작자(creator)라는 비율을 가져오면 Power BI 제작자는 약 525만 명. 여기에 배수를 10배로 잡으면 Fabric 제작자 52.5만 명, 100배로 잡으면 5.25만 명이 된다. 그다음 필요한 값이 조직당 평균 Fabric 제작자 수인데, 필자는 조사 결과(AI 로 교차 검증했다고 밝힌다)를 **7명**으로 잡는다 — 대기업은 수십 명, 중소 조직은 1~4명 수준을 뭉뚱그린 값이다. 10배 가정(52.5만 ÷ 7 = 75,000개 조직)은 마이크로소프트조차 주장하지 않는 규모라 배수가 틀렸음을 알 수 있고, 100배 가정은 **7,500개 조직**을 내놓는데 이는 전혀 다른 방법으로 얻은 6,300과 꽤 가깝다.

**세 번째 독립 경로: 90–9–1 참여 법칙.** 온라인 커뮤니티의 90%는 읽기만 하고, 9%는 가끔 기여하며, 1%가 콘텐츠 대부분을 쓴다는 확립된 경험칙이다. 필자는 r/MicrosoftFabric 의 고유 게시자 3,847명, 마이크로소프트 Fabric 커뮤니티 포럼의 고유 게시자 1,630명, 여기에 Fabric Discord 서버 멤버 2,600명을 더해 **8,077명**을 얻는다. 그리고 곧바로 이 숫자의 편향을 양방향으로 점검한다 — 세 플랫폼 간 중복이 전혀 없다고 가정한 값이고 Discord 는 실제 게시자가 아니라 전체 멤버 수이니 **과대**인 반면, 포럼 데이터가 2024년 9월까지밖에 없고 놓친 커뮤니티가 있을 수 있으니(다만 Stack Overflow 조차 Fabric 게시물이 300개 미만) **과소**일 수도 있다. 서로 상쇄된다고 보고, 이 8,077이 전체 제작자 커뮤니티의 5% 또는 10%를 대표한다고 놓으면 각각 161,540명 / 80,770명이 나온다. 여기에 이 숫자가 Fabric 이 존재한 3년 전체의 게시자를 포함한다는 점 — 써 보고 글도 남겼지만 지금은 안 쓰는 사람이 있다는 점 — 을 반영해 잔존율 33%를 적용하면 53,308명 / 26,654명이 되고, 조직당 7명으로 나누면 **7,615개 / 3,808개 조직**이 된다. 7,615는 앞의 두 추정과 잘 맞아떨어진다. 시작값 8,077이 낮다고 보고 두 배(16,154)로 잡아 같은 계산을 돌리면 15,231개 / 7,615개 조직이 나온다.

**결론 구간.** 필자는 하한 3,808개, 상한 15,231개 조직으로 잡고 **중간값 약 9,000개 조직**이 Fabric 을 쓰고 있으며 그중 3분의 1 정도만 의미 있는 프로덕션 투자를 했다고 본다. 이를 거꾸로 돌리면 9,000개 조직 × 7명 = 약 63,000명의 Fabric 제작자, 세계 인구의 0.000759%다. 필자의 표현으로는 커뮤니티라기보다 황무지에 가깝다 — 인구 100만 도시에 Fabric 으로 뭔가를 만드는 사람이 7~8명 있다는 뜻이고, 그 정도로는 사용자 그룹을 꾸려 봐야 매달 한두 명 나오는 모임이 된다는 것.

**비교 기준점 — Synapse.** 필자가 특히 인상적으로 꼽는 대목은 테크노그래픽 집계 데이터 등으로 계산했을 때 Synapse 가 정점에서 2.5만~3만 개 조직을 확보했던 것으로 보인다는 점이다. Fabric 은 거기에 한참 못 미친다. 자기 고객 기반에서도 Synapse 를 쓰던 고객 중 Fabric 으로 옮긴 곳은 하나도 없고 전부 Synapse 에 남아 있는데, 이유는 Fabric 운영 비용이 훨씬 비싼 데다 옮길 유인이 없기 때문이라고 말한다(해당 문장에 오타로 보이는 비교 대상 표기가 있으나 문맥상 Synapse 대비라는 뜻). 기존 워크로드가 비교도 안 되게 싼 값에 잘 돌아가고 있다는 것.

마무리에서 필자는 Fabric 고객 수가 적은 게 자신에겐 놀랍지 않다고 정리한다 — Synapse 고객도, Power BI 고객도, Snowflake·Databricks 사용자도, AWS·Google BigQuery 쪽도 옮겨 갈 설득력 있는 이유가 없다는 것. 그리고 독자에게 반증 데이터를 청한다: 당신 도시에 정기적으로 30명 이상 모이는 Fabric 사용자 그룹이 있는가, 아니면 30명 넘는 Power BI 그룹에 Fabric 을 만지는 사람이 한두 명 있는 정도인가.

**적용 각도(참고용 메모)**: 방법론 자체가 쓸 만하다 — 검증 불가능한 벤더 발표 수치를, 서로 독립적인 세 경로(SKU 전환 비율 / 커뮤니티 활동량 배수 / 90-9-1 참여 법칙)로 각각 추정해 값이 수렴하는지 보는 구조. AI 툴·모델의 "채택률" 주장을 평가할 때 그대로 옮겨 쓸 수 있는 틀이고, 각 가정(15% 제작자 비율, 조직당 7명, 잔존율 33%)을 명시해 반박 가능하게 열어 둔 서술 방식도 참고할 만하다.
